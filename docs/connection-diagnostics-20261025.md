# 断网、连接失联与任务中止（2026-10-25）

用户指出笔记本断网很常见，不能把“API连接中断”作为所有情况的统一解释。本轮新增结构化诊断；不启动模型、不切断真实网络、不重载现用 MCP、不修改旧 worker 安装。

## 当前能区分的情况

`ds_wait` / 状态摘要新增可选 `failure`：`kind`、中文 `label`、发生环节 `stage`、依据强度 `certainty`、时间，以及存在时的原始错误码/HTTP状态/本机接口观测。失败仍保留原任务 ID、工作区和原始已脱敏错误。

| 显示 | 判定依据及边界 |
| --- | --- |
| 调用方请求停止 | 当前桥确实接到该任务 stop 请求；不把普通 aborted 当成人工操作。控制器正常退出触发的停止另列。 |
| 疑似本机断网（无可用网络接口） | 网络类错误发生时，设备没有可用非回环、非链路本地地址。只记录接口有无，不暴露地址，也不声称测出了完整互联网故障原因。 |
| 网络路径不可达、DNS失败、请求超时、连接丢失 | 保留 ENETUNREACH、ENOTFOUND、ETIMEDOUT、ECONNRESET、UND_ERR_SOCKET 等上游依据和环节；不能据其中一个码断言整台 laptop 断网。 |
| 服务端限流 / 认证拒绝 / HTTP错误 | 明确 HTTP状态。限流或503不写成用户停止。 |
| 本地控制通道断开 | 本地 SDK/MCP通道异常；不直接算作 DeepSeek API故障。 |
| 原控制器已失联，状态待核实 | 原任务记录仍是执行中，原进程/owner 已不存在。由原来的 interrupted 改为 unknown；同一 read 守卫阻止 followup/openView/fallback 误重发。 |
| 运行时中止（未确认主动停止）/ 原因未确认 | 上游只给 aborted 或通用错误，没有更细证据。未知保持未知。 |

网络观测不主动 ping、探测第三方或调用模型。接口存在不意味着互联网可达，因此 `internetReachable` 保持 null。本轮没有实现自动付费续跑策略。

## 任务与连接分别处理

- Worker 观察/等待失败后保留远端身份和 unknown；恢复连接只查原 worker 状态，可取回原结果，不重新 start。真实任务是否继续运行取决于远端事实，不承诺断网后一定继续。
- 原生 SDK 抛错后沿用原来的专属进程清理；关闭得到确认时可以报告失败，清理失败则 unknown。原生执行不是云上持久在线进程，不能承诺断网期间持续生成；已写文件不会因这些标记回滚。
- 控制器正常关闭与意外消失分别报告。意外失联后尚无自动恢复裁决器；需核对原生日志、运行时及产物，不能为了恢复而绕过 unknown 守卫。
- 原版 DSH 正文界面保持；桥的任务状态栏与 worker 降级窗显示诊断标签。卡片读取失败显示“未确认执行中止”，不反向改变后台任务状态。
- 父模型 instructions 要求依据 failure 字段解释，不从“超时”“aborted”自行推断用户点停或 laptop 断网。

## 验证与发布边界

完整离线115/115通过，新增/强化：错误因果链与网络码、DNS/HTTP/超时/停止区分；真实本地 HTTP流在响应中途断开（实际 UND_ERR_SOCKET）；本机接口不可用的故障注入；控制器失联变 unknown 且没有第二次模型派发；worker 恢复后原 ID 收回结果、start次数仍1。已有停止隔离、冷续接、兜底守卫及界面构建保持通过。

没有把故障注入当成真实 Wi-Fi 断开实测。没有重载主实例或正在工作中的旧 worker；直接调用原 `deepseek_worker` 的历史错误格式不随本桥更新。新增标签需加载更新后的桥，宿主中的真实断网交互仍待实验窗口验证。

截图本身不足以追认那次是断网还是主动中止。只读查询关联旧 worker 后，能确认后来由父级接管并释放；该最终状态不能替代故障发生时的网络证据，也没有因此中断其他正在运行的任务。
