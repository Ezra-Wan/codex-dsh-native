## 真实正文传输的证据

探针通过当前 `createRuntime()` 启动官方 SDK+Web，并在发送 prompt 前，用本进程生成的 URL 经官方 `/connect` 认证，连接官方 `/api/remote.mux`，订阅确切 `session_id` 的 `session/follow`。未模拟服务、流帧或模型响应；不是浏览器自动化或历史回放。

成功回合 session：`7534ab0f-11a3-4b3f-88e2-3cde1f942052`，模型 `deepseek-v4-flash`，`effort=off`，`maxTokens=2048`，只读、无工具的纸飞机句子任务。

| 相对探针开始时间 | 观测 |
| --- | --- |
| 12,021 ms | 第一个正文片段，累计 1 字。 |
| 12,124 ms | 下一次正文增长，累计 2 字。 |
| 16,412 ms | 最后正文片段，累计 885 字；总计 592 个正文片段。 |
| 16,427 ms | SDK 收到 turn/end。 |
| 16,434 ms | Web follow 收到 turn/end；最终回复 885 字，finish reason 为 completed。 |

因此“同一回答结束前正文多次到达官方 Web 通道”成立。没有浏览器可见增长、像素、DOM、自动选中或完整逐字一致性证据，不能把此表扩写成宿主端到端通过。

首次传输探针没有显式关闭思考，2048 输出上限被耗尽，最终正文 0 字、`max-tokens`，已按失败处理。正式成功探针使用官方支持的 `off`。总共显式发起四个真实任务回合：用户实验窗口两次、独立传输探针两次；2048 是单请求限额，不能据此宣称任务总花费上限。

这也排除了“仅将通配端口改成固定 HTTP 端口”或“改用 localhost”可以修复的推断。来源声明补齐是协议层修正，**在本机不是可工作的承载修复**。这是特定安装构建的事实，不是所有 Codex 版本的一般承诺。

实际运行的 DSH 页面：启动 URL 返回 303，持有效认证访问首页返回 200；未返回 `Content-Security-Policy`、`X-Frame-Options`、CORP 或 COOP 禁嵌头。官方认证 Cookie 带 `SameSite=Strict`；跨站 iframe 中的认证仍是另一项待验证边界。HTTPS 规范化成功不代表可信证书、Cookie、WebSocket 与会话选择已经通过。
