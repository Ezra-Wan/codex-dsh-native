# v0.1.3-preview.1：按调用观察的源码预览

本版按2026-10-26确认的规则调整原生 DSH 观察方式。**代码和离线检查已交付，新的 Codex 宿主显示、真实模型流及完整操作回归等待用户回到电脑后验收。** 以前 v12 的目视结果不能代替本版 v13 的验收。

## 这次改变了什么

| 调用方式 | 对话流内 | Codex 侧边 |
| --- | --- | --- |
| `role:sub` | 只显示本次问题、响应和相应执行记录；结束后固定 | 同一个 agent 的完整原生会话历史，可用原生历史分页查看 |
| `role:peer` | 不挂载 DSH 正文；宿主可能仍保留工具行/简短侧边提示 | 查看该 agent 的完整原生会话历史 |
| 同一 agent 的 `ds_followup` | 新调用有自己的入口和记录范围，不重新展示前次正文 | 仍是同一个原生会话，前后历史连续 |

Codex 在派发时明确选择 sub/peer；不按运行任务数量猜测身份，不因其它任务结束而改变显示位置。显示开合继续使用 Codex 原生按钮，没有增加第二套收起按钮。peer 不强制自动弹开侧边。

原生日志保留一份。任务状态中增加 `observations` 元数据（调用 ID、记录起止位置、状态和已有结果文件路径），不复制整段消息。完整历史和上下文仍由 DSH 管理；显示范围不改变模型上下文。

流内收到原生 `turn/end` 后固定当次记录，之后不会跟随同一会话的新调用。控制器的后续状态请求保留 `call_id`。若 Codex 在 DS 仍执行时先结束本轮回复，可调用 `ds_observe(agent_id, call_id, freeze:true)` 固定目前已提交的记录范围；这不停止任务，也不代表任务完成。没有凭空增加“Codex 回复结束”宿主回调。

`ds_observe` 可补挂缺失或失效的入口，不再禁止正常观察调用，也不再承诺隐藏 `ds_wait` 等宿主工具行。

## 复用与存储边界

复用安装版 `@deepseek-ai/dsh-client-ui-conversation@0.2.1-rc.2` 的原生事件装配器、原生记录源和原生所有正文组件。另复制其 MIT `BoundConversation` 类，通过小型适配器提供当次事件窗口；没有手写聊天 DOM。来源、摘要和许可见 [第三方声明](../THIRD-PARTY-NOTICES.md) 及 `vendor/deepseek-bound-conversation/`。

正常完成后，调用范围随本地任务状态保存；重新打开同一 `call_id` 可读取原生日志。未提交的瞬态片段不额外写一份历史，崩溃后不能保证恢复这些片段。Codex 是否在重启/历史滚动后恢复原来的卡片，以及旧卡片能否原位重挂，仍需实际宿主验收。

任务列表优先使用宿主提供的 `_meta["openai/session"]`；该字段见 [官方文档](https://developers.openai.com/plugins/reference)。这是可选宿主信息，不能假定每个 Codex 版本都会提供。可用时也允许调用方传一致的 `conversation_id`；缺失时只列明确打开的任务，不回退成整个桥的任务列表。它用于界面归属，不是新增安全认证机制。

旧 worker 仍是明确标识的降级状态/结果/工具摘要窗口，不提供原生正文或完整原生历史；本轮没有宣称它实现了原生按轮次裁剪。旧安装保留，是否能调用取决于使用者的独立 worker 配置。

## 安装和升级

沿用 [上一预览的安装前提](preview-v0.1.2.md)，检出新标签 `v0.1.3-preview.1` 后运行 `npm ci`、`npm test`。DSH 版本仍固定0.2.1-rc.2，OPS/鲸鱼没有升级。

新规则使用 **`CODEX_DSH_UI=mcp`**；旧 iframe 兼容路径不提供本版记录裁剪，不能拿它验收新界面。原生资源地址升为 `ui://dsh-native/task-v13.html`，需要重载所选测试实例的 MCP 后加载新元数据；本轮未改主实例配置、未重载任一实例、未启动展示服务。

本机已有的主配置之前缺少上述 UI 开关，且旧 worker MCP 为 disabled：这是待用户回来处理的主实例迁移问题，不因发布源码预览自动修复。不要为了本轮界面测试误用主环境或反复发付费任务。

## 用户回来后的实际验收

1. 在隔离第二实例加载新 MCP 元数据，先使用零模型历史夹具，确认流内当次范围、侧边完整历史，以及关闭侧边后的布局。
2. 串行调用一个 sub，执行中确认正文多次增长；完成后记住第一处记录，再以同一 agent 续接。第二处只显示新问题/响应，第一处不变化，侧边包含两次历史。
3. 同时派发两个 peer，确认双方使用不同会话、只在侧边显示正文；切换、关闭侧边、其中一个完成，都不会恢复成流内正文窗口。
4. 在不同 Codex 对话分别调用，核实真实宿主是否传递对话身份；缺失时明确记录能力限制，不假称跨对话归属已端到端验证。
5. 验证按 `call_id` 补挂、冷历史恢复、主动固定仍在执行的调用、错误/断线展示；再回归原有工具详情、OPS、worker兜底和窗口布局。失败保留证据，不重复付费刷绿。

离线检查覆盖了真实 Cordis 加载/卸载、已安装原生装配器、原生加载清单解析器、实际卡片模块接线，以及真实 stdio 的调用元数据/对话归属。它们不能证明实际宿主界面已通过。
